# 检验科试剂管理系统

基于 **Python 3.10+（实测 3.13）+ Flask + SQLite/MySQL** 的检验科试剂全生命周期管理系统。采用「**盒（采购/出库单位）→ 瓶（最小使用单位）**」两级库存模型，支持每盒唯一条码、扫码枪出入库、按瓶登记实际消耗、50×30 标签打印，覆盖试剂入库、出库、科室使用、库存、效期预警、盘点、统计报表等完整业务。前端基于 Bootstrap 5，专业、美观、响应式，静态资源全部内置、**断网可用**。

Windows 上推荐使用 `install.ps1` **一键部署**（自动装依赖、注册看门狗与每日备份计划任务、建快捷方式、登录自启、启动服务），详见[一、Windows 一键部署](#一windows-一键部署推荐)。

## 一、Windows 一键部署（推荐）

### 1. 前置要求
- 服务器端：**Windows 10 / 11**（Python 3.9 起官方已不再支持 Windows 7，3.10+ 在 Win7 上装不上）。
- 已安装 **Python 3.10 或更高版本**，并勾选 *Add to PATH*（脚本会校验版本，低于 3.10 直接退出）。
- 客户端：科室其他电脑只要能开浏览器即可，Windows 7 老电脑也能正常访问（仅作浏览器客户端，不装 Python）。

### 2. 运行一键部署脚本

右键 `install.ps1` → *使用 PowerShell 运行*，或执行：

```powershell
powershell -ExecutionPolicy Bypass -File install.ps1
```

脚本会自动完成：

| 步骤 | 内容 |
|------|------|
| 1 | 检查 Python 是否存在且版本 ≥ 3.10（不满足直接报错退出，不会继续装依赖） |
| 2 | `pip install -r requirements.txt` 安装全部依赖（失败只警告，不中断部署） |
| 3 | 创建 `instance / logs / backups / exports / instance\signatures / instance\certs` 目录 |
| 3.5 | 递归清理项目内所有 `__pycache__`（避免旧的 .pyc 让新代码不生效） |
| 4 | 生成启动 / 停止 / 看门狗 VBS 脚本（`start_server.vbs`、`stop_server.vbs`、`watchdog.vbs`，GBK 编码） |
| 5 | 注册计划任务：**`ReagentServer_Watchdog`**（每 5 分钟检测崩溃自动拉起服务）、**`ReagentServer_Backup`**（每天 23:00 自动备份数据库） |
| 6 | 创建桌面快捷方式「试剂管理系统 / 停止试剂管理系统」，并把「登录自启」放入启动文件夹 |
| 7 | 立即启动服务并提示本机 / 局域网访问地址 |

> 卸载请运行 `uninstall.ps1`。

### 2.1 生成干净部署包（分发到其他电脑）

`dist/` 下的 ZIP 是"干净部署包"：只有源码与安装脚本，**不含**数据库、`-wal`/`-shm`、日志、备份、`secret_key`、`__pycache__` 和 `.git`，解压到新电脑直接运行 `install.ps1` 即可。

```powershell
python tools/make_deploy_package.py                    # 版本号取当天日期
python tools/make_deploy_package.py --version 20261116 # 指定版本号
```

- 产物：`dist/试剂管理系统_部署包_<版本>.zip`，根目录附 `部署步骤（请先看这里）.txt`
- 排除规则写在 `tools/make_deploy_package.py` 的 `EXCLUDE_DIRS / EXCLUDE_SUFFIX / EXCLUDE_NAMES` 中；新增运行时数据目录要同步加进去
- 包内保留空目录 `instance/`（含 `signatures`、`certs`）、`logs/`、`backups/`、`exports/`，避免首次启动因缺目录报错
- 两份培训 docx 会一并打包（内含科室人员信息与系统截图），对外分发时解压后删除即可
- 验证方式：解压到临时目录，用 `SQLITE_PATH` 指向临时库跑 `python init_db.py --empty`，再用初始密码登录，应得到 16 张表、1 个 admin、4 个存放位置

### 3. 初始化数据库（两种模式）

**先说明一件容易误解的事**：`install.ps1` 的第 3.6 步会调用 `python init_db.py --empty` 完成建库——只要 `instance\reagent.db` 还不存在，就建好全部数据表、创建 `admin` 账号（随机一次性密码写入 `instance\initial_admin_password.txt`）、写入 4 个默认存放位置；库里已有数据库时该步直接跳过，不动现有数据。随后第 7 步启动服务。所以"部署完成"时库里**不是空的**，已有表、管理员和存放位置，只是没有试剂、供应商等业务数据。

`init_db.py` 是在此基础上决定"要不要演示数据"，按用途二选一：

```powershell
# 演示模式（默认）：建表 + 三个演示账号 + 全套演示数据（15 种试剂、条码盒、出入库、使用记录）
python init_db.py

# 正式模式：仅建表 + 管理员（随机一次性密码），不造任何演示数据
python init_db.py --empty
```

- **演示模式会把已有 `admin` 的密码重置为 `admin123`**，并删除首启生成的 `initial_admin_password.txt`（因为文件里的随机密码已失效）；演示口令仅用于体验。
- `--empty` 模式下，若 `admin` 已存在（服务启动过一次），**保持原密码、不重新生成**，凭据文件也不会被覆盖；若该文件已被首次登录自动删除，请先确认之前是否跑过演示模式（那就是 `admin123`），否则用 `reset_admin_password.py` 重置。
- 库中已有业务数据（分类 / 试剂 / 入库单 / 条码盒任一存在）时再次运行会**跳过初始化**，不会覆盖；确需清空重建加 `--force`（可组合：`python init_db.py --force --empty`）。
- 凭据文件 `instance/initial_admin_password.txt` 在 **admin 首次登录成功后自动删除**，请登录后立即改密。

## 三、日常运维

### 启动 / 停止

| 方式 | 说明 |
|------|------|
| 桌面「试剂管理系统」快捷方式 | 启动服务并弹窗提示访问地址 |
| 桌面「停止试剂管理系统」快捷方式 | 停止服务 |
| `start_server.vbs` / `stop_server.vbs` | 与快捷方式等价（`start_server.vbs silent` 静默启动） |
| 登录自启 | 部署后已放入启动文件夹，登录 Windows 自动启动 |

### 看门狗与自动备份（install.ps1 已注册）

- **`ReagentServer_Watchdog`**：每 5 分钟检查 5000 端口，服务崩溃自动拉起；
- **`ReagentServer_Backup`**：每天 23:00 调用 `backup.py`，一次做完四件事——
  1. 用 SQLite 在线备份接口备份到 `backups/reagent_YYYYMMDD_HHMMSS.db`，**保留 30 天**；
  2. 清理 `exports/` 里 **7 天前**的 xlsx（所以导出目录的自动清理依赖这个任务）；
  3. 删除 `sys_oper_log` 中 **365 天前**的操作日志；
  4. 以上结果写入 `logs/backup.log`。
- **重要限定**：`backup.py` 里的 `DB_PATH` 硬编码为 `instance/reagent.db`，**只对 SQLite 有效**。切到 MySQL 后这个 23:00 任务不会备份任何数据（也不会清理日志/导出），须自行加 `mysqldump` 任务，或在库里手工清理。
- 手动备份：`python backup.py`；手动恢复：`python restore.py` 一键回滚（按需选择备份文件）。

### 日志
- 服务运行日志：`logs/server.log`（VBS/Waitress 启动时的标准输出）
- 错误堆栈：`logs/error.log`（500 错误的完整 traceback，RotatingFileHandler，单文件 2MB 轮转、保留 3 份；静默启动时查错主要看这里）
- 备份日志：`logs/backup.log`
- 操作审计：系统内「系统管理 → 操作日志」（存数据库，可导出 Excel，导出取最近 5000 条）

### 升级 / 重装
- 代码更新后重跑 `install.ps1` 即可（幂等：重复注册任务与快捷方式会被覆盖，不会重复报错）；
- SQLite 会自动补列，MySQL 需手工加列（见[四、数据库](#四数据库)）。

## 四、数据库

### 自动探测（默认）
`DB_TYPE=auto` 时启动自动探测 MySQL：
- 连得上 MySQL → 使用 MySQL 8.0；
- 连不上（服务未启动 / 密码错误）→ 自动降级 **SQLite**（`instance/reagent.db`），单机/局域网小规模最省事。

SQLite 已开启 WAL、外键约束与 15 秒写锁等待，减少 "database is locked"。

### 切换到 MySQL（多人同时操作 / 数据量大时）
1. 安装并启动 MySQL 8.0，数据库会自动创建，也可手动：
   ```sql
   CREATE DATABASE reagent_db DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
   ```
2. 用环境变量覆盖连接信息（也可改 `app/config.py`）：
   ```powershell
   # Windows PowerShell
   $env:MYSQL_USER="root"; $env:MYSQL_PASSWORD="你的密码"
   $env:MYSQL_HOST="127.0.0.1"; $env:MYSQL_PORT="3306"; $env:MYSQL_DB="reagent_db"
   $env:DB_TYPE="mysql"
   ```
3. 重新执行 `python init_db.py --empty` 与 `python run.py`。

> `DB_TYPE`：`auto`（默认）/ `mysql`（强制）/ `sqlite`（强制）。`SQLITE_PATH` 环境变量可覆盖 SQLite 库路径（自动化测试、临时实例用）。

### 结构迁移与启动自检

`create_app()` 每次启动都会做以下几件事（无需手工操作）：

| 启动动作 | 说明 | MySQL 是否生效 |
|------|------|------|
| `db.create_all()` | 建缺失的表，已有表与数据不动 | 是 |
| 自动补列 | 按 `PRAGMA table_info` 检查并 `ALTER TABLE ADD COLUMN`（`sys_user.signature_image`、`reagent_info` 证照 5 列 + `min_stock_unit`（最低库存预警单位）、`supplier` 证照 3 列） | **否，仅 SQLite** |
| 空日期修复 | 把 DATE/DATETIME 列里的 `''`、`0000-00-00%` 置为 NULL（恢复旧备份后常见 500） | **否，仅 SQLite** |
| 库存汇总自校准 | `reconcile_inventory()` 按实际在库盒重算 `inventory.quantity`，并补/删多余汇总行 | 两库都执行 |
| 默认数据 | 存放位置为空时写入 4 个默认位置；用户表为空时创建 admin（随机密码 + 凭据文件） | 两库都执行 |

- `migrate.py` **只补齐两个查询索引**（`ix_pack_stock_fifo`、`ix_inventory_reagent_expire`），不增删任何列、不改业务数据；升级到条码序列版本后执行一次即可。
- MySQL 下没有自动补列，升级时需手工执行对应 `ALTER TABLE`，或重建库后用「数据导入导出」把基础数据导回。

## 六、核心设计：盒 / 瓶两级库存

- **一盒（ReagentPack）**：采购与整盒出库的单位，每盒有唯一 **10 位条码**，是最小追溯单位。试剂档案中设置「每盒瓶数」（如一盒 12 瓶 / 96 人份）。
- **一瓶（最小使用单位）**：试剂盒出库到科室后，开盒使用时按实际瓶数登记。
- 盒状态机：
  `在库 in_stock → 已出库 issued → 使用中 using → 已用完 empty`；另有 `已报废 scrapped`。
- **已出库未使用量**：科室已整盒领出但尚未用完的瓶数单独统计；下次使用同一试剂时**优先消耗已开盒（使用中）的盒**，避免多盒开封。

### 典型业务流程

```
采购入库（登记盒数）
      │ 审核通过 → 为每盒生成 10 位条码 → 打印 50×30 标签贴盒
      ▼
中心在库（按盒 / 批次，FIFO、效期预警）
      │ 扫码或手动整盒出库（领用 / 质控 / 报废）
      ▼
科室已出库（issued，已开盒则 using）
      │ 扫码按实际瓶数登记使用
      ▼
剩余瓶数自动扣减；用完自动转 empty；统计“已出库未使用量”
```

### 功能模块

| 模块 | 说明 |
|------|------|
| 首页仪表盘 | 试剂种类、在库盒数、今日出入库、临期/过期批次、出入库趋势、分类在库占比、预警列表 |
| 试剂入库 | 登记 / 审核、按分类筛选、录入盒数与包装规格、过期拦截、审核后每盒生成唯一条码并打印、Excel 导出 |
| 试剂出库 | 扫码枪整盒出库或手动选试剂（按分类筛选）、检验领用 / 质控 / 报废、先进先出 FIFO 自动推荐批号、Excel 导出 |
| 试剂使用 | 开盒后扫码按瓶登记实际消耗、优先使用已开盒、自动计算剩余瓶数、在用盒列表、已出库未使用统计、使用记录导出 |
| 实时库存 | 中心在库（按试剂 + 批号 / 盒），在库盒数、在库瓶数、已出库未用瓶数、分类筛选 |
| 效期预警 | 临期、过期、低库存统一预警并给出处理建议；**库存预警口径由试剂档案选择按大包装或按最小单位** |
| 库存盘点 | 一键按盒快照盘点，录入实际盒数，自动计算差异，盘亏报废、盘盈补建盒 |
| 温湿度记录 | 冰箱/室温按天批量录入上午/下午温度与湿度、曲线图、按月筛选导出；质量记录不可删除，只能更正并留痕 |
| 性能验证 | 新批号入库后标记"已验证/未验证"，出库未验证批号时二次确认 |
| 证照管理 | 试剂医疗器械注册证（编号/有效期/注册人/代理人）与供应商经营许可证及图片归档 |
| 基础数据 | 试剂分类、供应商、存放位置字典、试剂档案（含采购单位 / 每盒瓶数 / 最小单位 / 最低库存预警单位） |
| 数据导入导出 | 基础数据一键导出多工作表 Excel，改完按名称匹配重新导入 |
| 备份恢复 | 每天 23:00 自动备份（保留 30 天，**仅 SQLite**），`restore.py` 一键回滚 |
| 统计报表 | 出入库趋势、出库类型占比、分类消耗、供应商采购金额、实际使用瓶数，Excel 导出 |
| 系统管理 | 用户管理（三类角色 RBAC）、操作日志审计与导出 |

> Excel 导出上限：单次最多 **5 万行**（`app/utils/common.py` 的 `MAX_ROWS`），超出部分会被截断并在控制台打印警告，请缩小时间范围或分次导出。导出文件含手写签名图片（签名存于 `instance/signatures/`）。

三类角色（RBAC，`app/utils/permission.py`）：

- **系统管理员 admin**：用户管理与签名、操作日志、数据导入导出（仅 admin 可用），以及全部业务功能；入库单可直接修改/删除（限待审核）。
- **试剂管理员 manager**：入库审核（通过/驳回）、出库确认（含以"组低耗员"身份确认）、盘点的创建与完成、基础数据维护（分类/供应商/存放位置/试剂档案增删改）、温湿度记录更正、批号性能验证标记、各类 Excel 导出、统计报表。
- **检验人员 staff**：入库/出库/使用申请与扫码登记、库存与预警查询、温湿度录入、报表与各业务记录查看（只读）；可导出自己的「使用记录」与「试剂出库汇总」。不可审核单据、不可改基础数据、不可做盘点和温湿度更正；入库/出库/库存/温湿度导出、操作日志、数据导入导出均需更高权限。

> 未通过权限校验的请求返回 403 页面；未登录一律跳登录页。

## 七、条码与扫码

### 1. 条码规则
- 每盒审核入库时自动生成 **10 位纯数字条码**：`yyMMdd`（6 位日期）+ 4 位当日序号（0001 起）。例如 2026-10-20 的第一盒是 `2610200001`。
- 每日最多 9999 盒；序号用一条原子 `UPDATE` 自增，**序列永不回退**，删除历史单据也不会复用条码。
- 前端使用 **JsBarcode（CODE128 编码）** 渲染。CODE128 可直接编码 10 位数字，**无需 EAN-13 校验位**，普通 USB 扫码枪即可识别。
- 条码生成逻辑见 `app/utils/common.py` 的 `gen_barcodes()`。

### 2. 扫码枪使用
- 扫码枪相当于「输入文本 + 自动回车」。在**试剂出库**或**试剂使用登记**页面左侧扫码框扫描盒条码即可：
  - 出库页：自动锁定该盒并带出试剂、批号、效期，提交后整盒出库；
  - 使用页：自动定位已出库的盒（在库盒会提示先出库），带出剩余瓶数后登记本次用量。
- 也可手动输入条码后按回车。

### 3. 标签打印（佳博 TSC TDP-245，50mm × 30mm）
标签页通过浏览器打印，已按 50mm × 30mm 排版（`@page { size: 50mm 30mm; margin: 0 }`），每枚标签含试剂名、批号、效期、每盒瓶数与条形码。

首次使用需在电脑上：
1. 安装 **佳博 TSC TDP-245 打印机驱动**；
2. 在系统「打印机和扫描仪」中添加打印机，并把纸张规格设为 **宽 50mm × 高 30mm**（必要时新建自定义纸型）；
3. 打开标签页点击「打印标签」，在浏览器打印对话框中：打印机选 TSC TDP-245、纸张 **50×30mm**、方向**纵向**、边距**无**、缩放 **100%**，建议关闭页眉页脚。

> 标签为前端网页打印，不依赖额外的 Python 打印组件，也不直连 TSPL 指令，跨浏览器、跨机器通用。

### 4. 试剂盒 DM 码（UDI）扫码识别

入库页顶部新增「扫试剂盒 DM 码」卡片：扫一下药监码，自动带出试剂、批号、有效期，不用再手敲。

**码里有什么**：试剂盒上的 Data Matrix（DM）码是 GS1 应用标识串，入库只用到 4 个：

| 应用标识 | 含义 | 例子 |
| --- | --- | --- |
| `01` | 产品标识 DI（14 位） | `06972487720754` |
| `17` | 有效期（YYMMDD） | `281231` → 2028-12-31 |
| `10` | 批号 | `B2601A` |
| `21` | 序列号（可无） | — |

**批号和有效期来自码本身，本地 UDI 库只负责回答「这个 DI 是哪个产品」**。解析器（`app/services/udi_service.py::parse_dm`）同时兼容带 GS 分隔符（`\x1d`）和真实扫码枪常见的无分隔符定长截断写法。

**本地 UDI 产品库**：表 `udi_product`，只存检验试剂子集（每日包 7 千多条里命中约 200 条），查询瞬间返回。导入命令：

```bash
# 只导检验试剂子集（推荐，默认行为）
python udi_import.py D:\下载\UDID_DAY_UPDATE_20261119.zip

# 先看命中多少条，不写库
python udi_import.py D:\下载\UDID_DAY_UPDATE_20261119.zip --dry-run

# 用全量包补历史产品（只导检验试剂子集，包内 1281 个 XML 会全部扫到，约 15~20 分钟）
python udi_import.py D:\下载\UDID_FULL_RELEASE_20261101.zip

# 解压后的目录同样可以传（目录下的 XML / ZIP 逐个导入）
python udi_import.py D:\下载\UDID_FULL_RELEASE_20261101

# 全量导入（含耗材、设备，约 640 万条，库会涨到几百 MB，不建议）
python udi_import.py D:\下载\UDID_FULL_RELEASE_20261101.zip --all
```

发布文件从 <https://udi.nmpa.gov.cn/download.html> 下载（每日包约 0.4MB、每周/每月包更大、全量包 300MB+）。**每日包和全量包都按要求处理：ZIP 里不止一个 XML 时会逐个扫描，不会只看第一个。**重复导入同一 DI 只更新产品信息，**已建立的 DI↔试剂绑定关系会保留**。

日常建议：先导一次全量包补齐历史产品，之后每月导一次月度包（或每周导一次周包）保持新增产品同步。

**匹配规则**：拿 DI 查到产品后，在试剂档案里按注册证号、名称、厂家打分——注册证一致 +100，名称去括号后相等 +80，名称互相包含 +45，厂家（注册人）一致再 +20。**只有「唯一最高分且 ≥75」才自动选中**：注册证一致但产品名完全不同（一证多产品的情况）只作为线索列出，同名的两条试剂（比如高值/低值质控品只差括号）分数并列时也不自动选，都交给人工点一下。候选最多列 5 个。DI 不在库里时，页面上仍会把码里的批号、有效期填进表单，只差选试剂。

**绑定记忆**：入库提交成功时，把「DI → 试剂」写进 `udi_product.reagent_id`；下次扫同一款盒子，直接自动选中上次用过的那项试剂。

**三种扫码方式**
- **扫码枪**：把光标放在扫码框里直接扣扳机。扫码枪等同键盘输入 + 回车，二维码里的原始串会整串进框并即刻解析（仓库现有的 CODE128 盒条码流程完全不受影响）。
- **摄像头实时扫码**：点「摄像头扫码」按钮，用内置的 ZXing（`app/static/vendor/js/zxing.min.js`，离线可用）从摄像头画面识别 DM 码。**浏览器限制：实时摄像头只在 `http://127.0.0.1:5000` 或 HTTPS 下可用**，用局域网地址打开时浏览器会禁用（页面会提示换方式）。
- **拍照识别（手机 / 局域网通用）**：点「拍照识别」，用手机拍一张试剂盒上的 DM 码（或从相册选），前端离线解码后走同一套识别流程。**上传照片不要求 HTTPS**，所以在局域网 `http://本机IP:5000` 下手机可以直接用；识别失败会提示重拍（靠近、放正、避反光）。

> 想让手机在局域网里**实时**摄像头扫码（不用拍照），只能给服务加 HTTPS（自签证书 + 手机信任）。日常用「拍照识别」已经够快，不必配证书。

入库页底部仍可手工填写，扫码只是加速，任何一步失败都不影响正常入库。

## 十、关键业务规则

- **两级库存**：入库按盒建条码（每盒 `total_units = 试剂.pack_size`）；出库默认整盒；使用按瓶登记。
- **先进先出**：手动出库按有效期从早到晚选盒；过期在库盒禁止领用/质控（仅可报废）。
- **使用前置校验**：在库盒（in_stock）不能直接登记使用，须先整盒出库；已用完/报废盒不可再登记。
- **优先开盒**：同一试剂有多盒已出库时，列表优先返回「使用中」的盒，再按效期排序。
- **超量保护**：单次使用瓶数不能超过该盒剩余瓶数，否则报错。
- **盘点**：以中心在库整盒为基准，盘亏盒报废、盘盈补建盒（自动生成新条码）。
- **效期状态**：剩余天数 `<= 试剂效期预警天数` 为临期；小于 0 为过期。
- **低库存预警口径**：每项试剂可自选「按大包装」或「按最小单位」比较——按大包装比中心在库盒数；按最小单位比**全科可用瓶数**（中心在库未开封 + 科室已出库未用完），因此已领到科室的试剂也算库存，不会因为"中心库房空了但科室还有"而误报。按瓶预警时补货建议折算为"约 N 盒"。最低库存填 0 表示该试剂不预警。设置入口：基础数据 → 试剂档案 → 编辑。
- **UDI 绑定**：入库时扫试剂盒 DM 码，DI 与试剂档案的绑定关系落在 `udi_product.reagent_id`；同一 DI 后续扫码直接复用上次的选择，UDI 产品信息可重复导入覆盖，绑定不会被清掉。
- **操作留痕**：关键业务动作（登录/登出、改密、用户新建与修改、入库审核、出库确认、使用登记、盘点、温湿度更正、批号验证、数据导入导出）写入 `sys_oper_log`，含操作人、账号、模块、内容、IP、时间。物理删除会被拒绝或替换为"停用"，以保留追溯链。
- **安全**：密码用 Werkzeug 默认的 **scrypt** 哈希（不是 PBKDF2）、ORM 参数化防 SQL 注入、Jinja2 自动转义防 XSS、所有 POST 走全站 CSRF 校验、首次部署生成随机一次性管理员密码、连续 10 次密码错误锁定 3 分钟（进程内计数，重启归零）、新密码最短 6 位。

## 十一、常见问题

1. **启动后显示 SQLITE？**
   未检测到可用 MySQL（服务未启动/账号密码不对）。按[四、数据库](#四数据库)设置 `DB_TYPE=mysql` 后重启。

2. **页面没有样式 / 图表 / 条码不显示？**
   前端资源全部内置在 `app/static/vendor/`，不需要联网。若显示异常，按 Ctrl+F5 强制刷新浏览器缓存。

3. **条形码扫不出来？**
   请用扫码枪扫描打印清晰的标签；CODE128 支持 10 位数字条码。屏幕上直接扫描请确保扫码枪处于英文输入法、CODE128 已开启。

4. **打印标签尺寸不对？**
   务必在驱动中建立 50×30mm 纸型，并在打印对话框选该纸型、无边距、100% 缩放、纵向。

5. **如何重置数据？**
   `python init_db.py --force` 清空重建演示数据；`python init_db.py --force --empty` 清空并回到正式空库。

6. **MySQL 报 caching_sha2_password 错误？**
   依赖中已包含 `cryptography`，请确认 `pip install -r requirements.txt` 成功。

7. **可以直接把 `instance/reagent.db` 拷走当备份吗？**
   不建议。SQLite 开启 WAL 后，服务运行中直接拷贝可能拿到不完整的数据。请用 `backup.py`（计划任务每天 23:00 自动执行，走 SQLite 在线备份接口），或用页面「数据导入导出」导出基础数据。

8. **忘了管理员密码？**
   正式模式首次部署的密码在 `instance/initial_admin_password.txt`（首次登录成功后自动删除）；之后忘记，可用 `reset_admin_password.py` 重置。

9. **运行 `init_db.py` 提示"数据库已存在业务数据，跳过初始化"？**
   这不是报错。说明库里已有分类/试剂/入库单/条码盒，程序按设计保护现有数据、不再灌演示数据；确实要演示数据请加 `--force`（会清空全部业务数据，正式库慎用）。

10. **切到 MySQL 后备份目录不再新增文件？**
   正常现象。`backup.py` 只备份 `instance/reagent.db`，MySQL 模式需自行安排 `mysqldump` 任务；每日 23:00 任务此时连日志/导出清理也不会执行。

11. **页面更新后样式没变化？**
   静态资源带 7 天浏览器缓存（`Cache-Control: max-age=604800`）。开发改样式可把 `STATIC_VERSION`（`app/__init__.py`）加 1 或按 Ctrl+F5 强刷。

12. **扫试剂盒 DM 码没反应 / 提示 DI 未收录？**
   先分清两件事：码里的**批号、有效期**一定能填进表单；「吃不准是哪个试剂」只是本地 UDI 库没有这个 DI。补数据的办法是下载药监局发布文件后执行 `python udi_import.py <文件>`（见[七、4](#4-试剂盒-dm-码udi扫码识别)）。若扫完完全无反应，检查扫码框是否聚焦（光标在框内）、扫码枪是否为键盘模式、以及是否把二维码当条形码扫（DM 码需扫码枪开启二维码/Data Matrix 支持）。

13. **点「摄像头扫码」提示不可用？**
   浏览器规定摄像头只能在 `http://127.0.0.1:5000`（本机回环）或 HTTPS 页面使用。用局域网 IP 打开时请改扫码枪，或在本机用 `127.0.0.1` 访问。
